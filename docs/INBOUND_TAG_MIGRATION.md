# Миграция inbound tag

Формат: `Протокол-Транспорт-сеть`, глобально уникальные суффиксы `-2`, `-3`.
Имена получаются из JSON, а не из старого суффикса. XHTTP REALITY остаётся
XHTTP; raw REALITY получает Reality; Shadowsocks по умолчанию поддерживает
TCP и UDP и называется `Shadowsocks-TCP+UDP-tcp+udp`.

## Применение

В проверенном checkout с настроенным доступом к Panel:

```bash
egames-fork check     # план, реальный Xray validator, без записи
egames-fork backup    # приватная резервная копия
egames-fork install   # миграция, затем обычная идемпотентная установка
egames-fork check
```

Источник истины — Config Profile API Panel 3.4.7. Node 3.4.3/Xray проверяются
обычным адаптером установщика. Установки без достоверного owner-state и с
изменёнными managed inbound отклоняются; чужие inbound не присваиваются.
Теги резервируются во всех профилях. Миграция обновляет объявления inbound,
вложенные `inboundTag`, paths/host_ids/inbounds/tag_labels служебного state.
`outboundTag`, selector балансировщика (это outbound selector), сетевые
параметры, UUID пользователей, ключи и remarks Hosts не переименовываются.
Ссылки старых тегов в subscription templates требуют отдельного адаптера:
установщик останавливается до записи. В рабочей проверке таких ссылок не было;
Node plugin также проверен отдельно и не содержит ссылок на старые inbound.

Panel удаляет прежние inbound UUID при переименовании. Поэтому снимок содержит
все Hosts, Nodes и Internal Squads. После PATCH новые UUID читаются по tag,
затем восстанавливаются точные прежние memberships и привязки. Отключённые
Hosts и исключения сквадов сохраняются. Проверяются API read-back, listeners,
соединение Node и Nginx. На короткое время при синхронизации доступ может
прерываться; обновление не является атомарной транзакцией между API-запросами.

## Резервные копии и откат

`/var/lib/egames-injector/backups/tags-*.json` — приватные снимки;
`tag-migration.json` — write-ahead журнал (0600 в каталоге 0700).
Файлы содержат секреты, не публикуйте их. При ошибке автоматический откат
восстанавливает конфиг и повторно определяет UUID по исходным tag, затем
восстанавливает Hosts, Nodes и Squads. Потеря HTTP-ответа после PATCH также
покрыта. При аварийном завершении запустите:

```bash
cd /opt/egames-fork
.venv/bin/python tag_migration.py --restore
```

Сначала исключите параллельные правки Panel. Команда отката возвращает снимок
до миграции и может отменить более поздние правки этого профиля/привязок.
Обычный `egames-fork restore` откатывает только последнюю обычную установочную
транзакцию и не является откатом переименования. Старые transaction history
сохранены для аудита, но автоматически не переигрываются: в них удалённые UUID.
`uninstall` после миграции блокируется, чтобы не удалить действующие связи.
Для полного возврата старой инфраструктуры используйте приватную резервную
копию БД и файлов после отдельной проверки — обычный restore её не заменяет.

`inbound_tag_plan.py` сохранён как исторический автономный планировщик имён
Host; он не применяет эту миграцию и не определяет новый стандарт названий.

После обновления проверяйте подписки и реальные соединения. Проверка серверных
listeners или внешний Xray-клиент не доказывают работу интерфейса Happ.
